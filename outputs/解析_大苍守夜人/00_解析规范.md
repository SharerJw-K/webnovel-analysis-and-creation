## 二、单章解析正文格式（`章节/第XXXX章_解析.md`）

必须严格按以下八节输出，标题层级与措辞固定，便于全书检索与横向比对。

> 篇幅口径（2026-11-01 二次修订）：以下各节标注的字数均为**参考下限**，不设上限。章节信息量大时可逐节扩写，不受原"150–250 字""800–1400 字"上限约束；唯一硬性要求是正文总字数不少于 800 字，且不写读后感。

```markdown
# 第XXXX章 章节标题

> 字数：N　｜　所属阶段：第X卷/某地名（若无法判定则写"未分卷"）

## 一、本章定位
一句话点明本章在全书中的功能（如"开局立人设""冲突引爆""过渡铺垫""势力登场""伏笔回收"），并标注功能标签：`[推进]` `[铺垫]` `[转折]` `[爆发]` `[过渡]` `[信息交付]`。

## 二、剧情梗概
参考 150–250 字（下限，可扩展），第三人称客观陈述，按事件先后顺序，不加评价，不剧透后文。

## 五、冲突与悬念
- 显性冲突：谁与谁、因何、以何种形式对抗
- 隐性张力：尚未爆发但已埋下的对立
- 信息差：读者已知而人物不知 / 人物已知而读者不知

## 六、章末钩子
引用原文收束句（不超过 30 字），并说明钩子类型：`悬念留白` / `反转预告` / `新敌登场` / `身份揭示` / `情绪悬置`。

## 七、剧情走向
本章把哪条线往前推了多远，分条列出：
- **主线推进**：……
- **支线推进**：……
- **人物成长线**：……
- **势力/世界观线**：……
- **后续预期**：读者读完本章会预期下一章发生什么（1–3 条）

## 八、承接关系
- **承上**：直接接续第 N-1 章的哪个动作/状态/悬念
- **启下**：为第 N+1 章留下哪些必须被处理的接口（人物在何处、要做什么、带什么情绪）
```

## 三、承接块格式（追加到 `00_承接链.md`）

每章解析完成后，向 `00_承接链.md` **文件末尾追加**以下 8 行块，不得修改前文：

```markdown
### 第XXXX章 章节标题
- 时地：当前时间点 + 主角所在地点
- 主线：本章主线推进的一句话结论
- 人物：本章人物状态变动（修为/身份/关系/伤势/所得）
- 新伏笔：新埋设的悬念（无则写"无"）
- 回收：本章**实际回收**的旧伏笔，≤3 条（无则写"无"）
- 章末状态：下一章开篇必须知道的全部前置信息，≤120 字
```

### 承接块硬性字数与写法约束（2026-11-01 修订，因台账膨胀而加）

| 字段 | 上限 | 写法 |
|---|---|---|
| 时地 | 40 字 | 时间点 + 一个主地点，不列地点串联 |
| 主线 | 120 字 | 一句话结论，可带分号 |
| 人物 | 200 字 | 只写本章**有变动**的人物，每人一句 |
| 新伏笔 | 150 字 | 只写本章新埋、且需跨章追踪的，≤5 条 |
| 回收 | 60 字 | 只写本章**确实回收**的，格式"第XXXX章伏笔X"；**严禁罗列历史未回收伏笔** |
| 章末状态 | 120 字 | 只写下一章开篇必须知道的信息 |

单块总长不得超过 700 字。若某章信息量过大，把细节留在正文，承接块只留接口。

> 修订说明：第 0236 章等早期块的「回收」字段被误写为"全书未回收伏笔清单"，单块长度达数千字，导致 `tail` 读取效率下降、台账可读性受损。自第 0237 章起按上表执行，历史块不回改。

### 「回收」字段的机器可读写法（强制）

`02_伏笔台账.md` 由脚本 `_build_foreshadow.py` 从本字段自动派生。为保证可解析，每个被引用的伏笔**必须写成 `第XXXX章伏笔X` 的 ID 形式并附状态标记**：

```
- 回收：第0236章伏笔①——（回收）；第0235章伏笔③——（部分回收）；第0234章伏笔⑦——（推进）；无
```

状态标记只允许四种：

| 标记 | 含义 | 台账效果 |
|---|---|---|
| （回收） | 本章已彻底解答 | 移入「已回收」 |
| （部分回收） | 解答了一部分 | 留在「在办」，标注部分回收章 |
| （推进） | 有新进展但未解答 | 留在「在办」，更新最近动向 |
| （未回收） | 本章提及但未解答 | 留在「在办」 |

未列出的伏笔即视为本章未涉及，不必罗列。**严禁**把历史未回收伏笔整表抄进本字段。

## 四、Agent 执行流程（强制顺序）

1. `Bash: tail -n 12 "outputs/解析_大苍守夜人/00_承接链.md"` —— 读取上一章承接块的「章末状态」，确认衔接点。
2. `Read` `02_伏笔台账.md` 的「一、重点跟踪」表（文件开头 40 行内）—— 确认本章是否回收其中某条，回收则按 §三 标记写入。
3. `Read` 本章原文 `大苍守夜人/第XXXX章 XXX.txt`（全文读，不跳读）。
4. 按 §二 八节格式写 `章节/第XXXX章_解析.md`。
5. 按 §三 格式把承接块追加到 `00_承接链.md`（用 Bash `cat >>` 追加，勿覆盖）。
6. 返回一句话：`第XXXX章 完成｜本章主线：……`

> 台账维护：每批次（约 20 章）结束后运行 `python _build_foreshadow.py` 重建 `02_伏笔台账.md`。单章 Agent 不直接改台账，避免并发写冲突。

## 五、连续性红线

1. **不得臆造**：原文未出现的人物、地名、数值一律不写；推断须标注"（推断）"。
2. **人称统一**：主角统一称"林苏"，不用"主角"代称。
3. **伏笔守恒**：本章埋下的伏笔必须进入承接块"新伏笔"，否则视为解析失效。
4. **接口闭合**：第八节"启下"必须与下一章承接块的"承上"可对上，出现断裂须回补说明。
5. **篇幅控制**：单章解析正文**不少于 800 字，不设上限**（2026-11-01 二次修订）。信息量大、人物多、事件密集的章节应充分展开，可写至 2000 字以上；表格不空行，不写读后感。
6. **以正文为限、少做臆测（2026-11-02 修订，自第 0701 章起执行）**：
   - 解析对象是**本章正文写了什么**与**它承接/留下了什么接口**，不是对后文的猜测。凡原文未写的人物动机、势力图谋、结局走向，一律不展开推演。
   - 「五、冲突与悬念」只写原文交代或明示的对立与信息差，不做人物心理外推（如"他其实在想……"）。
   - 「七、剧情走向 · 后续预期」**最多 2 条**，且必须是原文明确指向（章末动作、明言预告、直接威胁），不写"可能/或许/不排除"式的多分支罗列。
   - 「（推断）」标记仅用于**必须交代的衔接性判断**，全章不超过 2 处；能用原文事实说清的一律不用。
   - 宁可少写一条悬念，不可凭空补一条。
